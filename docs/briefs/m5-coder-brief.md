## 2. Design decisions (decided by the Orchestrator — implement as specified, document in code)

**D1 — GRAB rule: all five fingertip-to-palm-center distances below one curl threshold.**
`isGrabbing(landmarks, palmCenter) = FINGER_TIPS.every(tip => distance(palmCenter, landmarks[tip]) < GRAB_FINGER_CURL_THRESHOLD)` with `GRAB_FINGER_CURL_THRESHOLD = 0.08`. Why simplest-robust: (a) it reuses the exact palm-center geometry the classifier already computes for `isHandOpen`/`isPointing` — one symmetric boundary (a fingertip > 0.08 from the palm is "extended", < 0.08 is "curled"); (b) it reads only landmarks 0/9/tips, so the M2 synthetic-pose builder in gestures.test.ts stays valid UNCHANGED (a PIP/MCP curl-angle rule would need real joint positions the test poses interpolate linearly — angles would be meaningless); (c) it is the same normalized-unit distance family as every existing threshold (scale sensitivity is the accepted, documented M2 trade-off). Curl angles are REJECTED for now — document as a future refinement if real-camera tuning demands scale invariance. Intensity (curledness) = mean over the five tips of `clamp01(1 − dist/GRAB_FINGER_CURL_THRESHOLD)` (mirrors PINCH's tightness formula: → 1 for a tight fist, → 0 at the boundary). Confidence = fixed 0.90 (spec CV). Position = palm center (like OPEN/NONE) — the grab point is the palm. GRAB goes through the EXISTING `stabilize()` — it is a STATE gesture like PINCH/OPEN.

**D2 — Branch order: GRAB → PINCH → OPEN → POINT → NONE.** GRAB must be checked BEFORE PINCH because a fist has thumb+index close (it would satisfy PINCH's distance test); with GRAB first, a spec-conformant pinch (other fingers extended, ≥ 0.08) fails the all-five-curled test and falls through to PINCH, while a fist or "lazy pinch" (thumb-index close AND middle/ring/pinky curled) wins as GRAB — exactly the required precedence. `POINT_OTHER_FINGER_THRESHOLD` precedent applies to the new constant too: it duplicates OPEN_FINGER_THRESHOLD's 0.08 value under its own name so it can be tuned independently.

**D3 — SWIPE is an EVENT channel riding on top of the state channel; it never enters `stabilize()`.**
Per frame and per hand, after classify+stabilize produce the emitted gesture: push the palm-center world position into a per-hand `VelocityTracker` (imported from './animation' — reuse, because it exists, is unit-tested (M4), and adds zero new code; re-implementing a second history buffer in gestures.ts would duplicate tested logic). If the stabilized emitted type this frame is `OPEN` (first observation of an open hand is immediately stable, so a fresh appearing-while-swiping hand is not delayed), compute planar speed = `hypot(v.x, v.y)` from `getVelocity()` (z excluded: wrist-relative noise, same reasoning as M4 `buildMomentumSpec` zeroing z). Fire when: `armed && speed >= SWIPE_VELOCITY_THRESHOLD && nowMs − lastSwipeMs >= SWIPE_REFRACTORY_MS`. On fire: set `lastSwipeMs = nowMs`, `armed = false`, and REPLACE this hand's returned gesture for exactly this one frame with the SWIPE event. On ANY frame with speed < threshold: `armed = true` (re-arm). Refractory = 500 ms AND re-arm — both required — so one sustained fast sweep fires exactly once, and a fresh sweep after the arm returns/speed drops fires again at most every 500 ms. SWIPE never sticks by construction: the stability state is untouched (it still says OPEN), so the very next frame emits OPEN again. Exact emitted sequence for one swipe: `…, OPEN(t−1), SWIPE(t), OPEN(t+1), …`. Known documented edge: during the override frame the state channel continues underneath (a PINCH→OPEN transition mid-sweep still debounces normally). Confidence = fixed 0.88 (spec CV). Intensity = `clamp01(planarSpeed / (2 × SWIPE_VELOCITY_THRESHOLD))` (fires only at speed ≥ threshold, so emitted intensity ∈ [0.5, 1]; monotonic in speed — document). Position = current palm-center world position.

**D4 — SWIPE direction: dominant planar axis, scene coordinates.** `|vx| >= |vy|` → horizontal: `vx >= 0 ? 'right' : 'left'`; else vertical: `vy >= 0 ? 'up' : 'down'` (world +y is image-up because `landmarkToVector3` mirrors Y; world +x is image-right). Ties prefer horizontal (deterministic). Document that the strings refer to SCENE axes; if the user's on-screen preview is mirrored, real-camera tuning flips perception, not the math.

**D5 — SWIPE velocity threshold honesty (must appear at the constant AND in README).** Constants operate in WORLD units/s (gesture positions span −5..5 via `landmarkToVector3`). Spec: open hand > 20 cm in 200 ms = 1 m/s. If the ~10-unit interaction span corresponds to ~50–70 cm of real hand travel at arm's length, 1 m/s ≈ 15–20 world units/s. The chosen `SWIPE_VELOCITY_THRESHOLD = 2.5` is deliberately SENSITIVE (user-sanctioned 2–3 starting band) for first real-camera tuning: state BOTH numbers in the doc comment and README, with the tuning direction (raise toward 15–20 if ordinary hand motion triggers swipes). Velocity window: `SWIPE_VELOCITY_WINDOW_MS = 200`, `SWIPE_VELOCITY_WINDOW_SAMPLES = 7` (~200 ms at 30 fps — spec's window).

**D6 — PINCH_ZOOM is a separate method `recognizeBimanual`; `recognizeGestures` is untouched in behavior.** `recognizeGestures(hands: Hand[], nowMs: number = performance.now())` gains only the optional clock (existing callers/tests unchanged; HandTracker will pass its frame `now`). `recognizeBimanual(hands: Hand[], nowMs: number = performance.now()): Gesture[]` is new and self-contained: it RAW-classifies both hands itself (`classifyHand`, no dependence on the stability map or on recognizeGestures having been called — order-independent and deterministic). It fires only when EXACTLY two hands are present and BOTH raw-classify as PINCH. Primary hand = the hand with `handedness === 'Right'` if one exists, else `hands[0]` (deterministic; documented; the shared `Handedness` type is NOT extended — the bimanual Gesture carries the primary hand's `handedness`). Distance metric: planar (x,y only — z is wrist-relative PER HAND, so cross-hand z is meaningless; document) world-units distance between the two hands' thumb-index pinch midpoints (`landmarkToVector3(midpoint(THUMB_TIP, INDEX_TIP))` of each). State: a single bimanual slot `{prevDistance: number, lastMs: number} | null`. Per both-pinching frame: `d = planarDistance(m1, m2)`; if state exists and `dt = (nowMs − lastMs)/1000 > 0`, `rate = |d − prevDistance| / dt`; emit ONE Gesture iff `rate >= PINCH_ZOOM_MIN_RATE`; ALWAYS then update state to `{prevDistance: d, lastMs: nowMs}` (anchor advances every frame — a sub-deadband drift never accumulates into a later false emit). First both-pinch frame (state null) or `dt <= 0`: set anchor, emit nothing. Condition breaks (not two hands, or not both pinching): state = null, emit nothing — so one hand releasing resets the anchor; a later static re-pinch emits nothing until the distance CHANGES. Deadband `PINCH_ZOOM_MIN_RATE = 0.5` world units/s and intensity normalizer `PINCH_ZOOM_MAX_RATE = 5` world units/s are exported tuning constants (document the jitter rationale and tuning directions). Emitted gesture: `type: PINCH_ZOOM`, `confidence: 0.85` (spec CV), `intensity: clamp01(rate / PINCH_ZOOM_MAX_RATE)` (tracks the rate every frame while zooming), `position: world midpoint of the two pinch midpoints` (zoom center), `handedness: primary hand's`, `timestamp: Date.now()` (buildGesture convention), `zoomDirection: d > prevDistance ? 'out' : 'in'`. NOT passed through `stabilize()` — the deadband is its filter (document). While zooming, one PINCH_ZOOM per frame (a changing-distance stream); static two-hand pinch emits nothing.

**D7 — Bimanual identity in the merged payload: derived from `type`, NO `bimanual` field.** `PINCH_ZOOM` can ONLY be produced by `recognizeBimanual` (`classifyHand` never emits it), so the type IS the channel marker — a `bimanual?: boolean` field would duplicate information (YAGNI). Consumers: GestureDebug's per-hand section filters out `type === PINCH_ZOOM` BEFORE mapping (this also defuses the duplicate-`handedness`-key landmine), and its bimanual section renders the filtered-out entries; `App.summarizeGestures` renders bimanual entries as `zoom-in` / `zoom-out` tokens (no hand prefix — it is two hands) and per-hand entries exactly as today.

**D8 — Two timebases, never mixed (M4 lesson).** Velocity/rate math uses ONLY the injected `nowMs` frame clock (default `performance.now()`, matching HandTracker's `onResults` now); `VelocityTracker` ages relative to its newest sample, so the recognizer never compares absolute bases. Emitted `Gesture.timestamp` stays on the `Date.now()` base like every other gesture (App's momentum tracker pushes with `gesture.timestamp` — unchanged). Document this in the gestures.ts module docblock.

## 18. Pitfalls (each has bitten someone before)

- `enum` keyword → build fails (`erasableSyntaxOnly`). Missing `import type` for `SwipeDirection`/`ZoomDirection`/`Hand` → build fails (`verbatimModuleSyntax`). Unused import/param → build fails (tests compile too).
- Mixing timebases: `nowMs` (performance.now base) for ALL velocity/rate math; `Date.now()` only for emitted `Gesture.timestamp`. Never compare them.
- Putting SWIPE through `stabilize()` — the 3-frame filter would swallow or stick the event; the event channel must override the returned gesture for exactly one frame and leave the stability map alone.
- Forgetting to filter bimanual entries out of GestureDebug's per-hand `.map` → React duplicate-key crash the moment a Right-primary pinch_zoom renders next to a per-hand Right gesture.
- Using 3D distance for pinch-midpoint separation (z is wrist-relative PER HAND — cross-hand z is noise); or z in swipe speed. Planar (x, y) only, everywhere in M5 math.
- Editing an asserted console line or adding console output — verifier regression. HandTracker/App diffs must be surgical.
- Bumping the HUD title WITHOUT the v3/v4 lockstep edits in the same change — verifiers 3 and 4 fail (each pins the old string in TWO places: introspection finder AND check f/e). Record hashes before you start.
- Silently "fixing" M2 poses: only the E1 changes are sanctioned, with the per-pose rationale in the report; thumb/index coordinates of the pinch poses must stay byte-identical so the intensity math assertions are untouched.
- Non-deterministic tests: never rely on real elapsed time; inject every `nowMs` (the only clock-free call allowed is the E7 no-throw default-clock check).
- Headless FPS steady-state is 4–5 (SwiftShader): only the boot-window max ≥ 30 is asserted, exactly like M3/M4.
- The perf smoke (2000 iterations < 2000 ms) still covers `recognizeGestures`; the added tracker pushes are microseconds — if it regresses, you added something heavy (you shouldn't have).
